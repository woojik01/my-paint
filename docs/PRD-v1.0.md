# My Paint — 웹 드로잉 앱 개발 설계안

설계 버전: 1.0 · 작성일: 2026-10-23 · 상태: 개발 전 제안

- 대상 저장소: https://github.com/woojik01/my-paint
- 대상 환경: Android 스마트폰·태블릿 우선, Windows 및 데스크톱 브라우저 대응
- 언어: 한국어 기본, 영어 추가
- 배포 형태: PWA 웹앱 + Android TWA 패키지
- 핵심 원칙: 로그인 없이 사용, 기기 내 작업·저장, 핵심 기능 오프라인 제공
- 이 문서는 설계이며 저장소의 현재 구현 상태를 확인하거나 변경한 결과가 아니다.

## 1. 제품 목표

일반 일러스트부터 움직임을 위한 파츠별 원화까지 제작할 수 있는 그림 앱이다. 하나의 편집기에서 일반 드로잉과 파츠 작업을 제공하며 프로젝트 생성 시 선택한 작업 유형은 도구 배치와 초기 레이어 구성을 바꾼다. 작업 도중에도 전환할 수 있고 기존 그림은 변경하지 않는다.

앱에 표시되는 명칭은 ‘일반 드로잉’, ‘파츠 작업’, ‘움직임용 원화’, ‘레이어 PSD’로 통일한다. 사용자 요청에 따라 특정 외부 모델링 제품의 명칭을 UI, 튜토리얼, 템플릿 설명, 내보내기 도움말에 기재하지 않는다. 이 앱의 범위는 그림과 파츠 원화 제작이며 리깅·메시 변형·얼굴 추적·모델 실행은 포함하지 않는다.

## 2. 주요 사용 흐름

1. 홈에서 새 그림을 만들거나 최근 작업·프로젝트 파일을 연다.
2. 크기, 배경, 작업 유형을 정한다. 추천 크기는 1024×1024와 2048×2048이며 사용자 지정도 제공한다.
3. 브러시와 레이어를 사용해 그림을 그린다.
4. 파츠 작업에서는 부위별 그룹을 만들고 가려지는 영역을 별도 레이어에 보완한다.
5. 앱 내부에 자동 저장하며 원본 프로젝트를 기기 파일로 백업할 수 있다.
6. 용도에 맞는 이미지, 레이어 PSD, 파츠 묶음 또는 애니메이션을 내보낸다.

## 4. 레이어와 파츠 작업

### 4.1 공통 레이어

- 생성·복제·이름 변경·삭제·정렬·다중 선택·그룹화.
- 표시·잠금·불투명도·알파 잠금.
- 초기 합성 모드: 일반, 곱하기, 스크린, 더하기. 내보내기 지원 범위는 별도로 검사한다.
- 클리핑과 비파괴 레이어 마스크.
- 선택 레이어 병합, 그룹 병합, 보이는 레이어 병합. 원본 손실이 발생하는 작업은 실행 취소 가능하게 한다.
- 레이어 섬네일, 검색, 그룹 접기, 선택 레이어만 보기.
- 삭제된 레이어는 실행 취소로 복구하고, 프로젝트 삭제는 별도의 휴지통으로 처리한다.

### 4.2 파츠 작업 전용 도구

- 초기 그룹 템플릿: 얼굴, 눈 왼쪽·오른쪽, 눈썹, 입, 앞머리, 옆머리, 뒷머리, 몸, 의상, 장식. 생성할 그룹은 사용자가 선택한다.
- 눈 그룹 예시: 흰자, 홍채, 동공, 하이라이트, 위·아래 눈꺼풀.
- 선화와 채색을 분리해 작업하고 필요할 때 파츠 단위로 복제·병합한다.
- 다른 레이어를 흐리게 표시해 선택 파츠를 확인한다.
- 파츠 임시 이동·회전 미리보기: 실제 원본 위치는 유지하고 가림 뒤 빈 영역을 사용자가 점검하도록 돕는다.
- 가려진 영역 보완용 레이어 생성과 수동 덧그리기를 제공한다. 자동 보완이나 자동 파츠 분리를 필수 기능으로 잡지 않는다.
- 정면 중심선, 좌우 대칭 보조, 그룹별 표시 프리셋을 제공한다.
- 내보내기 전 빈 파츠, 중복 이름, 캔버스 밖 그림, 지원하지 않는 효과를 검사한다. 가림 영역의 완성 여부를 자동 판정했다고 표시하지 않는다.

### 4.3 파츠 전달 규칙

좌표 기준은 문서 왼쪽 위, 단위는 원본 픽셀이다. 기본 PNG 파츠 내보내기는 모든 파일을 문서와 같은 크기로 만들어 정렬을 유지한다. 용량 절약용 자르기는 별도 옵션으로 제공하며 원래 위치·크기를 JSON에 기록한다.

파츠 묶음 ZIP에는 파츠 PNG, 미리보기 PNG, manifest.json을 포함한다. manifest는 안정적인 레이어 ID, 이름, 부모 그룹 ID, 순서, 표시 여부, 불투명도, 원점과 크기를 저장한다. 파일명 중복은 ID 접미사로 해결하고 원래 이름은 유지한다.

## 5. 저장과 내보내기

프로젝트 저장과 완성 이미지 내보내기를 구분한다. 이미지 파일만 저장한 것을 편집 가능한 원본 저장으로 안내하지 않는다.

| 형식 | 지원 목표 | 보존 범위·옵션 |
| --- | --- | --- |
| .mypaint | 최초 공개 필수 | 레이어·그룹·마스크·문서 설정·사용한 브러시 설정·파츠 정보 보존. ZIP 컨테이너와 버전 있는 JSON, 타일 이미지로 구성 |
| PNG | 최초 공개 필수 | 합성 이미지, 투명 배경, 원본·선택 크기, 선택 영역 내보내기 |
| JPG/JPEG | 최초 공개 필수 | 합성 이미지, 품질 선택, 투명 영역을 채울 배경색 선택 |
| WebP | 최초 공개 필수 | 정적 이미지, 투명도와 품질 설정. 손실 없음 옵션은 선택한 인코더로 보장할 때만 노출 |
| PSD | 최초 공개 필수 | 8비트 RGB 레이어 PSD, 이름·순서·위치·그룹·투명도 중심. 합성 미리보기 포함 |
| SVG | 최초 공개 필수, 이미지 포함 방식 | 픽셀 레이어를 내장 PNG로 담고 그룹·좌표 반영. 자동 벡터 변환으로 안내하지 않음 |
| SVG | 후속 확장, 벡터 방식 | 벡터 도형·패스 도구로 만든 요소를 실제 벡터로 출력. 픽셀 요소는 내장 이미지로 유지 |
| GIF | 최초 공개는 정적, 후속은 애니메이션 | 정적 출력 후 프레임 편집과 연결. 팔레트 양자화 미리보기와 배경·투명 옵션 |
| 파츠 ZIP | 최초 공개 필수 | PNG 파츠 + 좌표 JSON + 합성 미리보기 |
| PNG 시퀀스·스프라이트 시트 | 애니메이션 단계 | 프레임 순서·지속시간 JSON 포함 |
| ORA·APNG·애니메이션 WebP | 추가 검토 | 구현·상호운용성 검증 후 별도 단계로 도입 |

Canvas toBlob은 PNG를 보장하지만 기타 형식은 브라우저에 따라 지원이 달라질 수 있다. 반환 Blob의 MIME과 파일 서명을 검사하고 요구 형식과 다르면 번들 인코더를 사용하거나 실패를 명확하게 표시한다. PNG 데이터를 다른 확장자로 저장하지 않는다. [S1]

GIF는 제한된 팔레트를 쓰므로 미세한 색과 반투명 가장자리에 변화가 생길 수 있다. 출력 전 결과를 미리 보여준다. 애니메이션 출력은 FPS, 프레임별 지속시간, 반복 횟수, 출력 크기를 설정한다. [S8]

SVG의 이미지 요소는 래스터 이미지를 포함할 수 있다. ‘이미지 포함 SVG’는 유효한 SVG지만 그림의 픽셀이 편집 가능한 벡터 패스로 변하지는 않는다. [S6]

### 5.1 PSD 호환성 계약

ag-psd를 브라우저용 읽기·쓰기 후보로 검증한다. 라이브러리 사용만으로 모든 편집기의 PSD를 완전 지원한다고 약속하지 않는다. [S2]

- 기본 출력: 8비트 RGB, 픽셀 레이어, 그룹, 이름, 표시 여부, 불투명도와 위치.
- 마스크·클리핑·합성 모드는 대상 도구에서 검증된 조합만 보존 모드로 제공한다.
- 호환되지 않는 효과는 영향 범위를 검사하고 복사본에서 렌더링하는 ‘호환용 출력’을 제공한다. 그룹 병합 등 레이어 분리가 줄어드는 변경은 내보내기 화면에서 표시한다.
- 원본 .mypaint는 수정하지 않는다. ‘편집 구조 유지’와 ‘보이는 결과 유지’가 충돌하면 사용자가 선택한다.
- PSD 불러오기는 후속 단계로 제공하며 지원하지 않는 조정 레이어·스마트 오브젝트·색상 모드는 제한 사항을 알린다. 가져오기와 내보내기의 지원 범위는 동일하다고 가정하지 않는다.
- 출시 기준은 실제 대상 도구에서 이름·그룹·좌표·알파·화면 합성 결과를 확인하는 것이다. 읽기·쓰기 왕복 검사만으로 외부 호환성을 확정하지 않는다.

## 6. 화면 설계

### 홈

최근 작업 격자, 새 그림, 파일 열기, 휴지통, 설정을 제공한다. 카드에는 썸네일·이름·수정일·문서 크기를 표시한다. 로그인이나 온라인 연결을 편집 진입 조건으로 삼지 않는다.

### 스마트폰 세로 화면

- 상단: 홈, 문서 이름과 저장 상태, 실행 취소·다시 실행, 내보내기.
- 중앙: 캔버스에 가능한 넓은 공간을 배정한다.
- 하단: 브러시, 지우개, 선택, 색상, 레이어. 세부 설정은 필요할 때 시트로 연다.
- 크기·불투명도 슬라이더는 접을 수 있도록 하고 왼손·오른손 배치를 지원한다.
- 패널을 열어도 현재 캔버스 중심이 갑자기 바뀌지 않게 한다.

### 태블릿·데스크톱

좌측 도구, 중앙 캔버스, 우측 레이어·색상 패널을 기본으로 한다. 패널 접기와 캔버스 집중 모드를 제공한다. 기기 이름보다 사용 가능한 실제 화면 폭으로 배치를 결정한다.

공통으로 48 CSS px 수준의 터치 영역, 시스템 안전 영역, 명도 대비, 도구 이름 접근성 레이블을 적용한다. 일시 알림은 약 5초 후 닫고 실패·복구가 필요한 메시지는 조치할 때까지 유지한다. 테마는 밝게·어둡게·시스템을 지원한다.

## 7. 오프라인과 데이터 보호

- Service Worker로 앱 화면, 스크립트, 기본 브러시, 폰트, 인코더, Worker 파일을 모두 캐시한다. 핵심 기능에 CDN이나 서버 호출을 요구하지 않는다. 캐시를 이용한 오프라인 제공은 Service Worker 기반으로 구현한다. [S3]
- 최초 접속 시 준비 상태를 점검하고 전체 필수 자산이 확보된 뒤 ‘오프라인 사용 준비 완료’를 표시한다. 처음부터 다운로드되지 않은 앱을 인터넷 없이 실행할 수 있다고 안내하지 않는다.
- 메타데이터·설정은 IndexedDB, 대용량 이미지 타일은 OPFS를 우선 검토한다. OPFS 미지원 시 IndexedDB Blob 저장으로 대체한다.
- 스트로크와 변경 사항을 짧은 묶음으로 저장하고 주기적으로 체크포인트를 만든다. 저장 완료 표시는 쓰기와 메타데이터 커밋이 성공한 뒤에만 바꾼다.
- 새 리비전 기록 → 데이터 무결성 확인 → 현재 리비전 포인터 갱신 순서로 처리한다. 중간 실패 시 마지막 정상 리비전을 연다.
- 이전 복구본을 제한된 개수 유지하며 강제 종료 후 복구 여부를 안내한다. 종료 직전 이벤트에만 저장을 의존하지 않는다.
- 저장 공간 추정, persistent storage 요청, 용량 부족 감지와 외부 백업 안내를 제공한다. OPFS와 IndexedDB는 기기 파일 백업과 같지 않으며 사이트 데이터 삭제 시 사라질 수 있다. [S4, S5]
- 사용자가 직접 내보내는 .mypaint 백업을 제공한다. 내부 자동 저장, 외부 파일 저장, 마지막 백업 시점을 별도로 표시한다.
- 저장 중 실패하면 편집 내용을 그대로 두고 저장 실패·재시도를 표시한다. 원본을 지우거나 성공으로 표시하지 않는다.
- 업데이트는 작업 저장 후 적용한다. 캐시 교체 시 프로젝트 데이터는 삭제하지 않으며 DB 변경은 버전별 마이그레이션과 복구 경로를 둔다.

## 8. PWA와 TWA 설치

웹 설치용 PWA와 Android APK/AAB 배포용 TWA를 구분한다. 웹의 설치 버튼은 가능한 환경에서 PWA 설치를 시작하거나 안내하고 TWA APK 설치는 별도의 Android 배포 경로로 제공한다.

필수 구성은 HTTPS, Web App Manifest, 앱 아이콘·maskable 아이콘, 일관된 start_url·scope, Service Worker다. Bubblewrap으로 Android 패키지를 생성하는 방식을 우선 검토한다. TWA는 웹사이트와 앱 간 Digital Asset Links 검증을 사용하며 실패하면 브라우저 UI가 있는 Custom Tab으로 표시될 수 있다. [S7]

- 최종 호스트의 루트 /.well-known/assetlinks.json에 패키지명과 실제 배포 서명 인증서 SHA-256을 게시한다.
- 소스 저장소와 웹 배포 주소는 별개다. GitHub 프로젝트 하위 경로에만 파일을 두는 것으로 도메인 루트 검증이 해결되지는 않는다. 루트를 제어할 수 있는 전용 호스트를 권장한다.
- 기본 방향은 자유 회전이며 세로·가로를 모두 지원한다.
- TWA 자체가 오프라인 파일을 모두 APK에 포함하는 것으로 가정하지 않는다. 실제 앱에서 오프라인 준비 완료 후 네트워크를 끊고 종료·재시작하는 검증을 한다.
- 파일 열기·다운로드·공유는 Android TWA 실기기에서 검증한다. 모바일에서 디렉터리 직접 쓰기 API 지원을 전제하지 않고 파일 선택·다운로드·공유를 기본 경로로 둔다.
- 뒤로 가기는 열린 시트·대화상자부터 닫고 홈으로 이동하도록 처리한다.

## 9. 구현 구조

제안 스택은 TypeScript + React + Vite, Canvas 2D 기반 초기 렌더러, Web Worker 기반 파일 인코딩·저장이다. UI 상태와 문서 픽셀 데이터를 분리하고 렌더러를 교체할 수 있도록 인터페이스를 둔다. 향후 WebGL2 합성은 실측으로 병목이 확인된 뒤 도입한다.

| 모듈 | 역할 |
| --- | --- |
| document-core | 문서·레이어 트리·마스크·파츠 메타데이터, 스키마 버전 |
| input-engine | 펜·마우스·터치 구분, 스트로크 샘플링, 제스처 |
| brush-engine | 보정, 필압, 브러시 마크, 타일 변경 |
| renderer | 레이어 합성, 축소 표시, 화면 좌표 변환 |
| history | 변경 타일 차이·명령 기록, 메모리 예산 |
| storage | IndexedDB·OPFS, 자동 저장, 복구, 마이그레이션 |
| import-export | 프로젝트·이미지·PSD·SVG·GIF·ZIP, 취소·진행률 |
| pwa | 캐시, 업데이트, 오프라인 준비 상태 |
| ui | 반응형 패널, 한국어·영어, 접근성 |

타일은 초기 256×256 단위를 검토하고 변경된 타일만 저장한다. 2048×2048 RGBA 픽셀 버퍼 한 장은 16 MiB이므로 레이어 50장을 전부 풀 버퍼로 유지하면 픽셀만 약 800 MiB이다. 히스토리·합성 버퍼까지 더해지는 구조를 피하고 빈 타일 지연 할당, 썸네일 분리, 활성 타일 캐시, 필요 영역 합성을 사용한다.

고정 ‘무제한 레이어’를 약속하지 않는다. 새 문서 생성 시 예상 부담을 표시하고 실제 기기 성능과 저장 공간을 기준으로 경고한다. 고해상도 제한은 실기기 측정 뒤 확정한다. 비동기 내보내기 중 편집 리비전을 고정해 서로 다른 시점의 레이어가 섞이지 않게 한다.

프로젝트 파일은 파일 수·확장 해제 크기·가로세로·타일 수를 검증한다. SVG 가져오기는 스크립트·이벤트 핸들러·외부 참조를 제거하거나 거부하고 격리된 경로에서 렌더링한다. 사용자 그림을 기본적으로 서버에 업로드하지 않는다.

## 10. 후속 애니메이션

프레임 생성·복제·삭제·정렬, 프레임별 지속시간, 재생·반복, 앞뒤 프레임을 흐리게 보는 어니언 스킨을 추가한다. 타임라인은 애니메이션 프로젝트에서만 노출한다. 레이어 트리와 프레임은 별도 데이터로 관리하고 변경 없는 셀은 참조 공유한다.

그림 그리는 과정을 녹화하는 타임랩스는 별도 기능으로 검토한다. 편집 실행 취소 기록과 장기 녹화 데이터를 동일한 것으로 취급하지 않는다.

## 12. 출시 검증 기준

1. 오프라인 준비 완료 후 비행기 모드에서 새 문서 생성·드로잉·레이어 편집·저장·앱 재시작·복원·모든 공개 내보내기 경로를 수행한다.
2. 저장 중 강제 종료·용량 부족·마이그레이션 실패 시 마지막 정상 버전이 유지되고 저장 성공 오표시가 없어야 한다.
3. .mypaint 재열기에서 레이어·그룹·마스크·파츠 좌표와 최종 픽셀 결과가 유지되어야 한다.
4. PSD는 대상 도구에서 그룹·한글 이름·레이어 순서·투명 가장자리·파츠 위치를 확인한다. 미검증 대상에 완전 호환 표시는 하지 않는다.
5. PNG/JPG/WebP/GIF/SVG의 실제 파일 서명·MIME·크기·투명 처리와 출력 결과를 확인한다.
6. 펜·손가락 전환, 두 손가락 제스처, pointercancel, 화면 회전, 시스템 바 영역에서 의도치 않은 선·버튼 가림이 없어야 한다.
7. TWA 실기기에서 서명 검증, 파일 열기·저장, 뒤로 가기, 오프라인 재시작을 확인한다.
8. 기준 기기에서 2048×2048 문서·일반 합성 20개 레이어 시나리오를 측정한다. 입력 응답·프레임 시간·내보내기 시간·메모리를 기록하고 지원 범위를 결정한다. 이는 측정 시나리오이며 성능 보장이 아니다.
9. 앱에 표시되는 모든 언어의 문자열과 기본 템플릿을 검사해 금지한 외부 제품 명칭이 노출되지 않는지 확인한다.
